# Triggers Implementation Plan

**Goal:** Make PR rules first-class "triggers": each has an id, event source (GitHub PR today), workspace, workflow, optional agent/model override, enabled flag, status and a delivery log, with CLI (`aorch triggers`), a TUI tab, a dashboard screen, test-fire and webhook secret/tunnel setup help.

**Context:** `Rule` in src/pr.ts already has optional `id`, `workspace`, `agent`, `model`, `enabled` fields but nothing reads them. Rules are stored in `<home>/pr.json` (`loadSettings`/`saveSettings`). Webhook handler is `githubWebhook` in src/server.ts; polling is `aorch pr watch` in src/cli.ts. `startPrRun(d, ref, opts)` in src/pr.ts starts the run via `engine.start({pipeline, task, repo, ref, autoApprove})`; `StartInput.workspace` is `string | false`. `aorch pr rule add|remove` exists. Keep `aorch pr …` working unchanged.

**Global constraints:** no Claude/Anthropic attribution or Co-Authored-By trailers in commits; TDD; `npm run typecheck && npx vitest run && npm run build` pass before each commit; additive changes only (old pr.json files must still load); never log or return the webhook secret in deliveries; deliveries log is capped.

### Task 1: Core — ids, enabled, workspace/agent/model wiring, deliveries log
**Files:** Create `src/triggers.ts`; modify `src/pr.ts`, `src/server.ts` (webhook), `src/cli.ts` (`pr watch` only); Test `test/triggers.test.ts`.
- `ensureIds(rules): Rule[]` gives every rule a stable id (`<repo-slug>-<workflow>`, de-duplicated with `-2`…); `loadSettings` applies it (do not write back until a save).
- `matchRule` ignores rules with `enabled === false`.
- `applyOverrides(pipeline, {agent?, model?})`: returns a pipeline whose `agent`-kind nodes (not gates/approvals, not manager-spawned) use that agent/model; used by `startPrRun` via new opts `workspace?: string|false`, `agent?`, `model?`, passed to `engine.start` (extend `PrDeps.engine.start` input type with `workspace`). When the rule has a `workspace`, its folder is the `repoDir` if no explicit `repoDir`/local mapping is found (use `getWorkspace(home, id)`; fall back to normal lookup).
- Deliveries log `<home>/triggers-log.jsonl`: `recordDelivery(home, d)` / `readDeliveries(home, {trigger?, limit?})` where `d = {at, trigger?: string, source: 'webhook'|'poll'|'test', repo, pr?: number, outcome: 'started'|'ignored'|'skipped'|'error', reason?, runId?}`; cap to the newest 500 lines on write; `lastDelivery(home, triggerId)`.
- Webhook and `pr watch` record a delivery for every event they act on or ignore (ignored: not a PR event / no rule matches / bad action; skipped: already reviewed, fork guard, errors from startPrRun → `error`), and pass the rule's `workspace`/`agent`/`model` to `startPrRun`. Bad-signature requests are NOT logged with body content (log nothing).
- `triggerStatus(rule, home)`: `'paused'` if disabled; `'error'` if last delivery outcome is `error`; `'idle'` otherwise (`'active'` if last delivery was `started` within 24h).
- Tests: ids unique/stable; disabled rule never matches; overrides touch only agent nodes; startPrRun passes workspace/agent/model to a fake engine; deliveries capped and filtered; webhook (use existing server test harness) records ignored/started.

### Task 2: CLI `aorch triggers`
**Files:** modify `src/cli.ts` (+ usage text, README table later); Test `test/triggers.test.ts` (pure helpers) — put formatting/arg-parsing helpers in `src/triggers.ts` so they are testable.
- `aorch triggers` / `list`: one line per trigger: id, status, repo, `→ workflow`, workspace, `agent/model`, events, last delivery (relative time + outcome). Empty state explains `aorch triggers add`.
- `add <owner/repo|*> --workflow w [--workspace id] [--agent a] [--model m] [--events …] [--labels …] [--comment] [--drafts] [--forks] [--id name]` (validate workspace exists, workflow resolvable via `pipelineFor`, agent known to the registry when given); `enable|disable|remove <id>`; `show <id>`; `log [id] [--limit n]`; `test <id> <pr-link-or-number>`: fetches the PR and runs the exact match logic (dry run by default: prints "would start workflow X on workspace Y with agent/model" or why it would be ignored; `--fire` actually starts it via `startPrRun` and records a `test` delivery); `setup`: prints secret (generating one if absent, like `pr secret`), payload URL, content type, events, and tunnel hints, and states whether the server is reachable on localhost.
- `aorch pr rule add` also accepts `--workspace --agent --model --id`; `aorch pr rules` unchanged.
- Tests for the helpers (id slug, relative time, status text, dry-run decision function `explainMatch(rule, pr)`).

### Task 3: Server API + dashboard Triggers screen
**Files:** modify `src/server.ts`, `web/src/api.ts`, `web/src/App.tsx`; create `web/src/Triggers.tsx`; styles in `web/src/styles.css`; Test `test/server.test.ts` additions.
- API (loopback-protected like the rest): `GET /api/triggers` → `[{...rule, id, status, last?: delivery}]` (secret never included); `POST /api/triggers` (create/update by id, same validation as CLI); `PATCH /api/triggers/:id` `{enabled}`; `DELETE /api/triggers/:id`; `GET /api/triggers/deliveries?trigger=&limit=`; `POST /api/triggers/:id/test` `{pr}` with `{fire?:boolean}` → explain/dry-run or fire; `GET /api/triggers/setup` → `{payloadPath, hasSecret, secretHint: last 4 chars, eventsToSelect}` and `POST /api/triggers/setup/secret` to (re)generate and return the secret ONCE.
- Dashboard tab "Triggers": table (status dot, repo → workflow, workspace, agent/model, events, last delivery), enable/disable toggle, delete, add/edit form (workspace dropdown from `/api/workspaces` if it exists else free text; agent/model from `/api/bots` listing), test-fire box (PR link, dry-run vs fire), delivery log pane, "Webhook setup" panel with secret reveal/regenerate and payload URL.
- Tests: list/create/patch/delete/test/deliveries/setup endpoints incl. validation errors and that no response ever contains the stored secret except the regenerate call.

### Task 4: TUI tab + README
**Files:** modify `src/tui.ts`, `src/ui.ts` (if rendering helpers), `README.md`; Test `test/ui.test.ts`/tui smoke.
