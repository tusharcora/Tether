# Team Runs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `team` run kind where Maestro is the single manager: a planning dialogue (option cards with a recommendation) before work, then a manager-led crew that consults (`@ASK`) and delegates (`@HAND`), run `live` in the chat or `autonomous`.

**Architecture:** A team run is a normal event-sourced run with `kind: 'team'`, a `planning` phase driven by new `plan.*` events, and a generated one-manager pipeline that reuses the existing manager/handoff machinery (`Engine.runManager`, `src/handoff.ts`). Worker questions to the user (`@ASK user:`) are new `user.ask`/`user.answer` events. Every surface (CLI, TUI chat, server/dashboard) reads questions from folded state.

**Tech Stack:** TypeScript (Node ≥22.12), SQLite event store, vitest, Solid dashboard.

**Spec:** `docs/superpowers/specs/2026-10-21-team-runs-design.md` (builds on `2026-10-21-team-handoffs-design.md`).

## Global Constraints

- Additive events only: old event logs fold unchanged; absent `kind` means `workflow`.
- No Claude/Anthropic attribution or Co-Authored-By trailers in commits.
- Planning: ≤4 questions per round, default 3 rounds (clamp 1..6); question `recommended` must be one of its option ids; ≤6 options per question.
- `@ASK user:` limited to 2 unanswered per run; extra ones are answered by Maestro with the recommended option and logged.
- Writes stay off unless the user answers yes in the dialogue (`allowWrites`); `planApproval` always on for team runs.
- Answers and free text are data: fenced when passed to agents (reuse the existing fence helper in `src/prompt.ts`).
- All new HTTP routes loopback-only like the rest of the API.
- `npm run typecheck && npx vitest run && npm run build` pass before every commit.

## Review Focus

- Answer arrives twice / for an unknown or already-answered question → 400/ignored, never double-applied.
- Run resumed or server restarted mid-planning → pending questions re-shown, no re-asking, no duplicate cards.
- Maestro returns malformed question JSON (missing recommended, empty options, 20 questions) → rejected with a fallback plain-text ask, run not stuck.
- User never answers (`--yes`/no TTY/autonomous) → recommended options used and recorded as such.
- Deleting or stopping a run while a card is pending → card disappears, no orphan awaiting node.
