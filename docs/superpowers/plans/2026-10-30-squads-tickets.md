# Squads and Tickets: plan

Spec: `docs/superpowers/specs/2026-10-30-squads-tickets-design.md`. Boards: `docs/design/squads-tickets/{Squad,Message,Tickets}.dc.html`. Branch `feature/squads-tickets` (teams-telegram #30, optional-run-budgets #31 and runs-fix-themselves #32 merged in). One implementer, tests first for server logic, small plain commits.

## Shape (my calls)

- **Tickets live on the goals table.** A ticket is a goal row plus ticket columns (`num`, `stage`, `priority`, `assignee`, `reviewer`, `labels`, `prs`, `squad`, `activity`) and a `ticket_keys` table (per project: the next number and an edited prefix). The loop engine (`src/goals/loop.ts`) keeps running goals as it does; nothing is copied or dropped, so the migration cannot lose data. The ticket status is the field `stage` (`backlog`, `todo`, `in_progress`, `in_review`, `done`, `canceled`); the goal's own `status` stays the loop engine's state.
- **Criteria are the old goal's finish check (one auto-checked criterion, the command) plus its manual tracker items** (ticked by people). Run items stay the ticket's run history. One auto-checked criterion per ticket.
- **Keys:** `<PREFIX>-<n>`, numbered per project in creation order and never reused (a counter, not `max+1`). The prefix is the last word of the project name, letters and digits, upper-cased, at most 4 (`acme-web` → `WEB`, `orchestrator` → `ORCH`), until someone edits it (`PUT /api/tickets/prefix`); an edit renames every key of the project, as Linear does.
- **Squads keep their internal name `team`** (types, `src/teams/`, the `Teams` class) so the stored data, the Telegram links and the tests of PR #23/#30 stay valid; everything a person reads says Squad, and the API is `/api/squads`. The on-disk folder moves once from `<home>/teams/` to `<home>/squads/` (same ids, same files; skipped when `squads/` exists, so it is idempotent and never overwrites).
- **Aliases:** the server rewrites `/api/goals*` to `/api/tickets*` and `/api/teams*` to `/api/squads*` before routing, so both answer identically for one release. `GET /api/squads` returns `squads` and the old `teams` key (the same list).
- **Status writer** (`src/teams/voice.ts`): templates for the events that only restate facts (work started, plan accepted, auto-fixing round n, needs you, merged, could not merge); the model writes only when there is a report to condense (finished, failed, gave up). Model choice: a squad agent bound to a free model first (`isFree` from attempts), else the speaking agent's own binding. Every output is validated (≤ 280 characters, ≤ 2 sentences, no headings, lists, code fences or tables, every @mention a squad member, a failure says so plainly); anything else falls back to the template. Agent answers to pings carry the same rules in their prompt and are flattened (markdown out, first two sentences) when they break them; the raw text is always kept on the message as `report`.
- **What I did** is built from facts the server has: files from the chain's diff, +/−, the gates that ran with their results (`24 passed`), duration, model. No "Read" row: reads are not recorded reliably.
- **Threads:** a person can reply in a thread; an agent's message triggered by another agent's message goes in that message's thread, except the first review of a hand-off, which is a channel message (it is the verdict people wait for).
- **Ship it** approves the ship card, opens the PR and merges it once its checks pass (the teammate's press is the "merge it"). **Undo** shows while the PR is not merged yet: it closes the PR, stops the merge watch and puts the card back to pending. **Not yet** is Send back: an optional reason, then the agent reworks once (the existing reject path).
- **Right now** status lines come from the live step (`recent()` of its streamed activity: "editing Tabs.tsx", "running npm test"), else the agent's state; progress is steps done of steps.
- **Unread** counts are per viewer: the sidebar keeps the last-seen time per squad in localStorage; the server sends the times of the latest non-owner messages.
- **Team runs** (the manager-led run kind) keep working underneath; their UI copy says "Squad run". The `tether team` CLI command is unchanged.
- **Board view** shows Backlog, Todo, In progress, In review, Done; Canceled is in the List view and its own filter. List columns: key, type, title, status, priority, assignee, squad, updated.
- **Recurring tickets** are loop goals (a check and a loop/schedule); the UI says Recurring; schedules keep targeting them.

## Added 2026-10-30 (boards 8 and 10 updated: fill blank space with real data)

- **Squad pulse** (right rail when no thread is open; the thread panel replaces it): the squad's tickets per status (Todo, Doing, Review, Done; each opens the board filtered to the squad and that status), Shipped today (key, title, PR) with a 5-day shipped bar chart, Coming up (queued pickups and the squad's recurring tickets with their next scheduled time), Pinned (any message pinned from its hover menu; a message with a link reads "Link", else "Decision").
- **Queue** (my call, it is what "busy · will queue" and "picks up next" need): a task for an agent that already has a live run in the squad waits in the squad's queue and starts when that run ends; "Start now" starts it at once. No ETA is shown ("queued", "next"): Tether cannot know how long the current run takes.
- **This week** strip on Tickets: shipped this week with a per-day chart, in flight with who, average Todo → Done (created to done, tickets done this week), the oldest ticket waiting on you (amber, opens it).
- **Ideas from your chats** (Backlog): goal cards a chat drafted and someone answered "Just answer, no goal"; "+" makes a Backlog ticket from the draft (and it leaves the list). **Ready for an agent** (Todo): a free squad agent suggested for each unassigned Todo ticket of its squad (Assign), and each queued pickup (Start now). Each box is hidden when it has nothing real.
- Tickets get a done time: `endedAt` is set when a ticket reaches Done or Canceled (by its loop or by its PR), cleared when it opens again.

## Tasks (in order)

1. **Tickets migration** (`src/goals/store.ts`, `src/goals/tickets.ts`, `test/tickets.test.ts`): columns and `ticket_keys`; `migrateTickets` numbers unnumbered goals per project in creation order, maps status → stage (paused not started → Todo, paused → Backlog, active → In progress, needs_you → In review, met → Done, stopped → Canceled), assignees → assignee/reviewer (the loop's agent first), a team assignee → squad. Round trip test, run twice, keys in creation order, nothing else changed.
2. **Squads migration** (`src/teams/store.ts`, telegram store): the folder move; round trip test (teams, channel, telegram state), twice is harmless, an existing `squads/` wins.
3. **Ticket model** (pure, `src/goals/tickets.ts`): `nextStage` for run and loop events (started → In progress, approval asked / PR opened → In review, sent back → In progress, merged → Done, loop status map, met with an open PR → In review), `prefixFrom`, `keyOf`, criteria and `ticketView`. Tests first.
4. **Tickets service** (in `Goals`): runs linked to a ticket move its stage and write activity; after a linked run finishes the auto-checked criterion runs in its worktree; manual stage changes (Canceled stops a loop, Backlog pauses one, Done ends it). Tests with the goals rig.
5. **`/api/tickets`** (`src/goals/routes.ts`): list/stream/create/patch with ticket fields, comments (`@agent` hands it work through its squad), Start, Merge PR, Send back, prefix; aliases. API tests.
6. **Status writer** (`src/teams/voice.ts`): `checkVoice`, `flatten`, templates, `writeStatus` with an injected model call. Tests: voice rules, fallback, mention resolution, failure messages, no network.
7. **Squad service** (`src/teams/teams.ts`): messages through the writer, `report`/`work` on messages, hand-off chips, threads and thread replies, reactions, ship card facts and Ship it/Undo/Not yet, tickets from squad asks (and their runs linked), live agent status, summaries (needs count, unread times). Update the teams tests to the new voice.
8. **Telegram**: copy says squad; squad messages in the new voice (no raw output); test.
9. **Web Tickets** (`web/src/tickets/`): Board, List, filters, detail panel, New ticket, ticket card in chat; Goals screen removed; `#/goals` redirects to `#/tickets`. Component tests.
10. **Web Squad channel** (`web/src/squads/`): header, Right now strip and filter, channel (hover actions, What I did, hand-off chip, reactions, thread link), thread panel, ship card states, typing line, Chat | Map, composer chips and @ picker with availability; New squad; sidebar Squads (live dot, unread, needs-you) and Agents (face, live status); `#/teams/<id>` redirects to `#/squads/<id>`. Component tests.
11. **Copy sweep**: Goals → Tickets and Teams → Squads where a person reads it (Home, Inbox, Runs, Builder, ⌘K, Settings, Telegram).
12. **Docs**: `docs/reference.md`, `docs/HANDOFF.md` (rename sections, how to check this build in the app).
13. **Check**: `npm run check` (known `evolve.test.ts` load timeouts confirmed alone), `npm run build`.
