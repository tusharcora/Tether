# Evolve Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let each bot's harness (persona, guidance notes, skills) improve from run outcomes and user feedback through evidence-backed lessons and reviewable, versioned proposals — the Harness² method implemented natively.

**Architecture:** A per-bot versioned harness store under `<home>/harness/<bot>/`; additive `feedback` and `harness` fields on events; a reflector that turns finished runs into lessons in the vault; an editor agent that proposes small diffs from confident lessons; an optional budgeted probe that replays recent tasks through current vs candidate harnesses; the user accepts/edits/rejects, which creates the next version. No auto-apply.

**Tech Stack:** TypeScript (Node ≥22.12), SQLite event store, vitest, Solid dashboard.

**Spec:** `docs/superpowers/specs/2026-10-21-evolve-design.md`.

## Global Constraints

- Editable surface is ONLY `persona`, `guidance[]`, `skills[]`; never permissions, limits, write access, bindings, tools. Violations are dropped with a reason.
- A proposal has ≤5 edits; each edit cites ≥1 lesson id; per-edit size cap 400 chars; guidance list ≤12 items.
- A lesson is `tentative` until it has ≥3 distinct supporting runs (config `minRuns`, default 3); tentative lessons are never proposed.
- Probes require an explicit budget (`--budget $`); no budget → no probe; probe spend recorded and capped.
- Rejected edits are fingerprinted (sha1 of bot + field + normalised text) and never re-proposed.
- Feedback, lessons and harness text are data: fenced when placed in prompts (existing fence helper in `src/prompt.ts`).
- Additive events/fields only; old logs fold unchanged. No Claude/Anthropic attribution or trailers in commits.
- `npm run typecheck && npx vitest run && npm run build` pass before every commit.

## Review Focus

- Bot has no history / one run only → `evolve` says "not enough evidence" and proposes nothing.
- Conflicting evidence (same lesson both good and bad) → stays tentative, never proposed.
- Accepting a proposal while another version was created meanwhile → refused with a clear conflict message (compare base version).
- Rollback to a version that is already current / does not exist → clear error, no change.
- Deleted or edited built-in bots: harness v1 is snapshotted from the current definition; resetting a bot does not erase history.

### Task 3: Reflector and lessons

**Files:**
- Create: `src/lessons.ts`
- Modify: `src/engine.ts` (call `reflect` after `run.finished`, best-effort, never fails the run), `src/vault.ts` only through its existing public write API
- Test: `test/lessons.test.ts`

**Interfaces:**
- `interface Lesson { id: string; bot: string; text: string; polarity: 'do'|'avoid'; evidence: { run: string; node: string; signal: string }[]; runs: number; status: 'tentative'|'confident'; updatedAt: string }`.
- `extractLessons(sigs: StepSignal[]): Omit<Lesson,'id'|'status'|'updatedAt'>[]` — rule-based: ≥2 redos → "avoid: gets sent back (reason from gate/verdict text when present)"; repeated handoff refusals; consistent thumbs-down note text; fast+cheap+approved → "do: keep doing what worked" only when feedback up. No model call in this task.
- `mergeLessons(existing: Lesson[], incoming: …, minRuns = 3): Lesson[]` — merge by normalised text similarity (token Jaccard ≥0.7), union evidence by run, `runs` = distinct runs, `status = 'confident'` iff `runs >= minRuns` and no opposite-polarity lesson with equal text; ids stable (`bot-<hash8>`).
- Storage: `loadLessons(home, bot): Lesson[]` / `saveLessons(home, bot, ls)` as JSON under `<home>/harness/<bot>/lessons.json`, plus a vault note per confident lesson at `lessons/<bot>/<id>.md` (links neutralised via `neutralizeLinks`).
- `reflect(home: string, s: RunState, vault?: Vault): Promise<Lesson[]>`.

- [ ] **Step 1: Write failing tests**: each extraction rule; merge idempotence (reflecting the same run twice does not raise `runs`); confidence threshold at 2 vs 3 distinct runs; conflicting polarity stays tentative; vault note written only for confident lessons; reflect failure (unwritable dir) does not throw.
- [ ] **Step 2–4:** run → implement → run. Commit `Evolve: reflector and lessons`.

### Task 4: Propose (editor agent, validation, rejection memory)

**Files:**
- Create: `src/evolve.ts`
- Modify: `src/cli.ts` (`aorch evolve <bot>`, `aorch lessons [bot]`), `src/adapters/mock.ts` (`MockScript.proposal`)
- Test: `test/evolve.test.ts`

**Interfaces:**
- `interface Proposal { id: string; bot: string; base: number; edits: Edit[]; createdAt: string; status: 'open'|'accepted'|'rejected' }` with `Edit = HarnessEdit & { lessons: string[]; domain?: string }`.
- `validateEdits(bot: BotDef, base: Harness, raw: unknown, lessons: Lesson[], rejected: Set<string>): { edits: Edit[]; dropped: { reason: string }[] }` — enforce editable fields only, ≤5, size cap, guidance ≤12, each cites existing confident lesson ids, fingerprint not in `rejected`.
- `fingerprint(bot: string, e: HarnessEdit): string`.
- `proposeFor(o: { home: string; bot: BotDef; registry: AdapterRegistry; agent?: string; model?: string; since?: string }): Promise<{ proposal?: Proposal; reason?: string }>` — builds the editor prompt from confident lessons (fenced) and the current harness; returns `reason:'not enough evidence'` when there are none. Open proposals are stored at `<home>/harness/<bot>/proposals/<id>.json`; `acceptProposal(home, id, pick?: number[]): Harness` (uses `saveVersion` with `expectBase`), `rejectProposal(home, id): void` (records fingerprints in `rejected.json`).

- [ ] **Step 1: Write failing tests**: validation drops edits touching forbidden fields (`permissions`), oversize, uncited, tentative-lesson-citing, previously rejected; max 5 kept; `proposeFor` with no confident lessons → reason; mock editor produces a proposal; accept creates vN+1 and marks accepted; accept with stale base → `HarnessConflict`; accept subset by index; reject remembers fingerprints so the same scripted proposal is dropped next time.
- [ ] **Step 2–4:** run → implement → run. Commit `Evolve: proposals`.

### Task 5: Probe and compose

**Files:**
- Modify: `src/evolve.ts` (`probe`, `compose`), `src/engine.ts` (a `startProbe` helper that runs a read-only replay in a throwaway worktree with a given harness override), `src/cli.ts` (`--probe --budget --tasks`)
- Test: `test/evolve.test.ts`

**Interfaces:**
- `interface ProbeResult { task: string; baseline: Score; candidate: Score; verdict: 'better'|'worse'|'tie'; costUsd: number }` with `Score = { gatesPassed: boolean|undefined; redos: number; costUsd: number; durationMs: number; judge?: number }`.
- `probe(o: { home; bot; proposal: Proposal; budgetUsd: number; tasks: number; engine: Engine; judge?: JudgeFn }): Promise<{ results: ProbeResult[]; spentUsd: number; stoppedBy?: 'budget' }>` — picks up to `tasks` recent comparable finished runs (same bot, read-only steps), replays each through baseline and each candidate edit set; stops cleanly when `spentUsd` would exceed `budgetUsd`.
- `compose(proposal: Proposal, results: ProbeResult[]): Proposal` — keeps edits whose candidate was `better` or `tie`-with-lower-cost in a majority of tasks; with no results returns the proposal unchanged. Probe spend appended as `manager.cost`-style events on the probe runs (they are normal runs, deletable).
- Budget required: `probe` throws `Error('probe needs a budget')` when `budgetUsd` is not > 0.

- [ ] **Step 1: Write failing tests**: no budget throws; budget exhaustion mid-way returns `stoppedBy:'budget'` with spend ≤ budget; compose keeps/drops edits by majority; tie handling; a probe never writes to the user's repo (assert throwaway worktree path and that the source repo HEAD is unchanged).
- [ ] **Step 2–4:** run → implement → run. Commit `Evolve: probe and compose`.
