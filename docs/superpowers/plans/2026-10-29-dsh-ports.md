# Ports from deepseek-harness: implementation plan

> One implementer builds the whole plan, task by task; the controller reviews at checkpoints.

**Goal:** six working parts of deepseek-harness (dsh) re-implemented against Tether's code: their algorithms, constants and test cases, not dsh's runtime plumbing.

**Spec:** `docs/superpowers/specs/2026-10-29-dsh-ports-design.md`. Source (read-only, MIT, © 2026 DeepSeek): `/Users/tushar/Documents/PROJECTS/deepseek-harness/deepseek-harness/packages/`.

## Global constraints

- Branch `feature/dsh-ports`. One commit per task; plain messages, no trailers. No push, no merge.
- Every ported file starts with `// Ported from deepseek-harness <package> (MIT, © 2026 DeepSeek).`; `THIRD_PARTY_NOTICES.md` carries the dsh MIT text.
- dsh tests become vitest tests in `test/` (vitest only collects `test/**/*.test.ts` and `web/src/**`), keeping their cases where Tether has the same behaviour.
- No new npm dependencies. Temp homes only in tests. Schedule and spill files 0600. Every new route validates its input (400).
- `npm run check` = typecheck, tests, build. The script did not exist; task 0 adds it.

### Task 0: `npm run check` and the notices file

- `package.json`: `"check": "npm run typecheck && npm test && npm run build"`.
- `THIRD_PARTY_NOTICES.md`: the dsh MIT license and the list of ported packages (extended per task).

### Task 1: Tool-result pruner

- dsh `compaction/compaction-tool-result-pruner` (`src/index.ts`, `src/config.ts`; test `tests/tool-result-pruner.spec.ts`).
- New `src/adapters/prune.ts`: `pruneText(text, cfg = DEFAULTS)` cuts a text over `thresholdChars` (8192 code points) to head 4096 + marker + tail 1024, counting Unicode code points so a surrogate pair never splits; `pruneToolResults(messages)` applies it to every `tool` message before the latest assistant turn (in place, so a second pass is a no-op).
- `src/adapters/openai.ts`: call `pruneToolResults(messages)` before each model call.
- Test `test/prune.test.ts`: defaults, code-point measure, head/tail without splitting surrogates, zero head and tail, converges in one pass, latest turn untouched.
- **My call:** the marker states how many characters were dropped (the spec asks for it; dsh's marker is fixed), so its length is bounded in the budget check. No `resolveConfig`: nothing in Tether configures the budgets, so dsh's config-validation cases are not ported. Rich-block cases do not apply (OpenAI tool results are strings).

### Task 2: Repeat-call reminder

- dsh `guard/repeat-tool-reminder` (`src/index.ts`; test `tests/repeat-tool-reminder.spec.ts`).
- New `src/adapters/repeatGuard.ts`: `RepeatGuard` (one per `run`) with `observe(name, args)`: deep key-sorted canonical JSON, consecutive identical count, the gentle text at `thresholds[0]` (3) and the detailed text (tool, count, arguments capped at 500 chars) at 5 and 8. Never blocks.
- `openai.ts`: every tool call (failed ones too) is observed; a reminder is appended to that tool result.
- Test `test/repeat-guard.test.ts`: escalation, gentle keyed to `thresholds[0]`, preview cap with full-key detection, a different call resets, property order ignored deeply, one guard per run.
- **My call:** no include/exclude patterns, no config validation, no user-interjection reset (Tether's loop has no interjections and no config for this).

### Task 3: Spill for oversized `run_code` output

- dsh `spill/spill-policy` (`src/retention.ts`, `src/notice.ts`, `src/index.ts`), `spill/spill-local` (`src/store.ts`, `src/cleanup.ts` age rule); tests `tests/retention.spec.ts`, `tests/spill-policy.spec.ts` (plain-text cases).
- New `src/codemode/spill.ts`: `spill(dir, text, max)` writes the full text to `<workdir>/.tether/spill/<random>.txt` (dir 0700, file 0600, `wx`), returns head + `[...]` + tail within `max` + dsh's notice (`(Omitted N bytes. Full formatted result stored at: <rel path>. <hint>)`), hint naming `repo.read(path, { from, to })` / `repo.search`. `retain(text, budget)`: half the budget to each end, never splitting a surrogate pair. `sweepSpills(dir, now)` deletes regular files older than 24 h (strictly older; symlinks and other entries untouched).
- `src/codemode/session.ts` `runCode`: where it cut the output, spill instead (falls back to today's cut when the write fails). `close()` sweeps the session's workdir.
- Server start: sweep `<home>/worktrees/*` and each workspace folder.
- Test `test/spill.test.ts`: retention cases (text-only), oversized → file + notice within the cap, small unchanged, 0600, `.tether` never in `git status`, sweep age rule.
- **My call:** `.tether/.gitignore` containing `*` instead of a line in `.git/info/exclude`. Same effect (git ignores the folder, so spills never reach a diff or a commit), but it also works in a linked worktree (whose `info/exclude` lives in the user's main repo) and in a folder that is not a git repo, and it never edits the user's git config. Images and the PTC dispatch-log arm do not apply.

### Task 4: Browser MCP presets

- dsh `experimental/browser-use-playwright-mcp`, `browser-use-chrome-devtools-mcp` (`src/index.ts`, pinned versions in `package.json`: `@playwright/mcp` 0.0.80, `chrome-devtools-mcp` 1.9.0).
- `src/codemode/mcpServers.ts`: `MCP_PRESETS` (`playwright`: `npx -y @playwright/mcp@0.0.80 --browser chromium --isolated --headless`; `chrome_devtools`: `npx -y chrome-devtools-mcp@1.9.0 --no-usage-statistics --isolated --headless=true`). `GET /api/codemode/mcp` also returns the presets; nothing is added until the owner clicks one.
- `web/src/settings/McpServers.tsx`: a "Presets" row with an Add button per preset not yet added (PUTs it under its name).
- Tests: server preset shape, web add-preset click.
- **My call:** the second preset is named `chrome_devtools`: Tether's MCP names allow no `-`. Headless launch, like dsh's default.

### Task 5: GitHub issue and comment triggers

- dsh `webhook/webhook-github` (`src/handler.ts`, `src/body.ts`; test `tests/handler.spec.ts`).
- `src/pr.ts`: `Rule.on?: 'pr' | 'issue' | 'comment'` (absent = `pr`), `Rule.label?`, `Rule.mention?`; `parseIssue(event, body)`, `parseComment(event, body)`; `matchRule` only matches PR rules; `issueTask` (title + body or comment fenced as data, with the link); `startIssueRun`.
- `src/triggers.ts`: rule identity is repo + workflow + kind; `parseRuleArgs` reads `on`, `label`, `mention`; `matchIssueRule`.
- `src/server.ts` webhook: after the HMAC check, require the event and JSON object body (dsh's 400s), then `issues` (opened, labeled) and `issue_comment` (created) start a run; the delivery is recorded like a PR run. The test endpoint refuses non-PR rules.
- Web: `TriggerForm` gets "Fires on" (pull request / issue / comment) and the label or mention field; `TriggerCard` shows the kind.
- Tests: `test/triggers.test.ts` (parsers, matching), `test/triggers-api.test.ts` (webhook issue/comment start a run, bad requests rejected, PR rules unchanged), web form test.
- **My call:** issue and comment runs fire only for authors GitHub marks OWNER, MEMBER or COLLABORATOR (anyone can open an issue on a public repo, and the run executes on this machine), and never for bot comments (no loops). Redeliveries are de-duplicated through `pr-seen.json`. No comment is posted back for these runs.

### Task 6: Cron schedules

- dsh `schedule/schedule` (`src/domain.ts`: `CRON_FIELDS`, `cronFieldValues`, `parseCronExpression`, `cronDateMatch`, `nextCronTarget`; test `tests/cron.spec.ts`).
- New `src/schedules.ts`: `parseCron` (dsh's strict five-field dialect and messages, Vixie day-of-month/day-of-week rule), `nextFire(cron, after)` in local time with `Date` (DST: a time in a skipped hour fires at the first minute after the gap; a repeated hour fires once, the earlier), store `<home>/schedules.json` (0600) with `{ id, name, cron, workspace, target, enabled, nextAt, lastRunAt?, lastRunId?, lastError? }`, `Scheduler` (30 s ticker, `tick(now)`, `runNow(id)`), routes `GET/POST /api/schedules`, `PATCH/DELETE /api/schedules/:id`, `POST /api/schedules/:id/run`.
- Catch-up: a schedule whose `nextAt` passed while the app was closed runs once on start, then `nextAt` moves past now.
- Targets: `workflow` → `engine.start` in the workspace folder; `goal` → `Goals.kick` (check, then propose the next run; a run in flight or one waiting for the person is left alone).
- Web: a Schedules section on the Triggers screen (list with next fire, switch, Run now, delete; form with cron + presets).
- Tests: `test/schedules.test.ts` (cron.spec cases that do not depend on Temporal zones, DST in a pinned zone, store, ticker, catch-up), `test/schedules-api.test.ts`, web test.
- **My call:** `nextAt` replaces a created-at base: one field gives the next fire for the list, the due check and the catch-up rule, and re-enabling or editing the cron recomputes it from now (no burst of old fires). `origin` is skipped: main has no run origin field yet.
