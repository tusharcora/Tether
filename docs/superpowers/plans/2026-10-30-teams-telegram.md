# Teams Phase 2: Telegram — implementation plan

**Spec:** `docs/superpowers/specs/2026-10-30-teams-telegram-design.md` (§2 = owner decisions, hard requirements). Base: `2026-10-29-teams-design.md` §6.8, §6.9. Boards: `docs/design/teams/Telegram.dc.html` (5), `docs/design/teams-telegram/TeamPeople.dc.html` (7).

**Shape:** Telegram is a transport over the existing `Teams` service. Inbound updates become `Teams.post` / `Teams.decide` calls with a `Person` resolved from the Telegram user; outbound, a change listener on the team's messages sends or edits the Telegram copy. Permissions live in `Teams` (so the Tether room, the Inbox and Telegram share one rule). Voice notes go through a ported SenseVoice recognizer in a child process; photos go to the agent's model through a new `images` field on an agent request.

## Security checklist (the point of this build)

- Only linked chats act; an unlinked group may only `/pair <code>`, a private chat only `/iam <code>`; everything else is dropped with an update id in the log, never its text.
- Telegram bot users (`is_bot`), anonymous admins and channels are never people: they cannot talk to agents, approve or start anything.
- Permission checks run before anything starts: a task, loop, `/new` or proposal Start from a person without "Can start runs" never reaches the engine or Goals (proposal card instead). Hand-offs inherit the asker of the chain.
- Approve / reject / merge: only people on the approver list (`'any'` = any person in the team; agents are never people). Agents never approve: a decision always carries a `Person`.
- Token: secret store only (account `telegram`), read only when `accounts.json` says Telegram is connected (so tests never read the Keychain); used only in the request URL to `api.telegram.org` (the Bot API has no other way), scrubbed from every error and log line; file download URLs are never stored or returned.
- Audio: downloaded from Telegram to a temp dir, decoded with the Mac's own `afconvert` (or `ffmpeg`), transcribed in a local child process, deleted after. The only network fetch in the speech path is the model download from Hugging Face.

## Tasks

1. **Data and rules** — `Person` gets `via`, `tgUserId`, `username`, `canStartRuns`, `joinedAt`; `mayStart(team, personId)`; `cleanTeam` accepts `place: 'telegram'` (no `link` from the client, approvers default `['owner']`, the owner always kept in a list); Slack still refused. Tests: `teams-rules`, `teams-store`.
2. **Teams service** — change listener (`onMessage`) fired for every new or changed message; `post` options `to` (reply-to an agent's message), `images`, `force: 'task'` (for `/new`); asker carried through hand-offs (`TeamTask.by`); a task/loop from a person without "Can start runs" → proposal card "Maya asked: …" + a once-per-person note; proposal Start checks the presser; people: `addPerson`, `setPerson` (approver / can start runs), `removePerson` (never the owner); goal `next` asks decided in the Inbox settle the team card (`hooks.decided`); Inbox parity: team runs' attention items say the team and place, loop-ship cards (no engine node) become Inbox items decided through the team; posting into a Telegram team from Tether is refused (read-only mirror). Tests in `teams.test.ts` / `teams-api.test.ts`.
3. **Bot API client** (`src/teams/telegram/api.ts`) — `call(method, params)` over `fetch`, JSON; 429 waits `retry_after` (bounded, abortable); errors carry Telegram's description with the token scrubbed; `download(file_path, max)` with a byte cap. Tests with a mocked fetch.
4. **Telegram state + rendering** (`store.ts`, `render.ts`) — `<home>/teams/telegram.json` 0600: offset, bot, owner, one-time codes (pair per team, `/iam`), per team: pinned status id, team message → Telegram message ids (newest 300), mute-until. Render a team message as HTML ("**Bolt**: …"), cards with inline keyboards (Approve / Reject / Diff; Start run / Edit / Dismiss), a run card's step track, decided cards "✓ Approved by Maya · 14:02"; the pinned status text. Pure tests.
5. **Bridge** (`bot.ts`) — handle one update: `/pair`, `/iam`, unlinked/other ignored, people registered as they speak or join, text → `Teams.post`, reply-to routing, callbacks (decide, diff, edit via a force-reply prompt), `/status`, `/runs`, `/new`, `/mute`, group → supergroup migration. Outbound: per-team serial queue, send new agent/Tether messages, edit changed ones with a ≥ 3 s gap per message (latest wins), mute skips non-approval posts, pinned status edited (debounced) and re-pinned only when lost. Tests with a fake API.
6. **Polling, account, routes, server** — long poll `getUpdates` (timeout 25 s, offset persisted after each batch, backoff 1 s → 60 s, stops on disconnect or a 401), `connect(token)` checks `getMe`, stores the token, sets the command menu; `disconnect()` stops and deletes. Routes: `POST/DELETE /api/accounts/telegram`, `GET /api/telegram`, `POST /api/telegram/iam`, `POST /api/telegram/voice`, `POST /api/teams/:id/pair`. Provider `telegram` (kind `key`) in Settings → Accounts.
7. **Photos** — `AgentRequest.images` (local files); OpenAI-compatible adapter sends them as `image_url` data URIs; Claude gets `--add-dir` + a line naming the files (its Read tool reads images); `runTurn` passes `body.images`. `readsImages(agent, model)`: Claude yes, OpenRouter models tagged `images`, else no → "this agent's model can't read images".
8. **Voice (SenseVoice port)** — `src/stt/` from dsh `experimental/speech-to-text-sensevoice`: `config`, `download-error`, `model-sources`, `runtime` (pinned assets, sha256-verified download to `<home>/models/sensevoice/`), `inference`, `worker` (IPC instead of the loopback HTTP server), `recognizer` (one serial worker, idle stop, queue cap); new `decode.ts` (OGG/Opus → 16 kHz mono PCM16 via `afconvert`/`ffmpeg`, WAV chunk walk). Bridge: voice → notice when not ready, else transcript "Voice: …" posted as a reply, then handled like typed text. `sherpa-onnx-node@1.13.8` (the port's pinned version) in `dependencies`. THIRD_PARTY_NOTICES entry. Tests: ported unit tests + a fake worker over the real IPC boundary + decode with a fixture.
9. **Web** — Settings → Accounts → Telegram (token, status, privacy hint, `/iam` code, voice model download + progress); sidebar New team → Telegram group; New team form for Telegram shows the pairing code and waits for `/pair`; team room for a Telegram team: T mark, read-only (no composer), **People and permissions** dialog (board 7); Inbox decides loop-ship team items through the team.
10. **Packaging and docs** — `npm run app` with `TETHER_APP_OUT` in the job tmp dir; check the bundled `sherpa-onnx-node` loads with the app's own binary as Node (`ELECTRON_RUN_AS_NODE=1`, exactly how the worker runs) without launching the app; reference.md Telegram setup; HANDOFF next step.

## My calls

- **Reply-to pings:** replying to an agent's Telegram message pings that agent (board 5's "why is this red?" has no @mention). A plain message to nobody stays a message.
- **Owner on Telegram:** the owner's Telegram user is `Person` `owner` with their Telegram first name, so cards read "Approved by Tushar"; decisions made in Tether still say "you" there and the owner's Telegram name in the group once `/iam` is done.
- **Approvers:** the owner always stays an approver of a Telegram team (board 7's disabled switch); turning a person's switch off when approvers is `'any'` turns it into the explicit list of everyone else. Phase 1 Tether teams keep their rule.
- **Loops from a person without the permission** become a proposal card too; Start creates the loop.
- **Hand-offs** inherit the person who started the chain; a run's result hand-off inherits whoever started (or approved the proposal for) that run.
- **Reject from Telegram** has no reason field (buttons only); the agent's one rework runs without a reason.
- **Diff button** replies with the diff stat and the first ~3 500 characters in a code block (no file upload).
- **Edit button** sends a force-reply prompt; the reply becomes the task (Start is still permission-checked). Prompts live in memory (lost on restart; the card's Start still works).
- **`/runs`** shows run id, title, status and cost, plus the PR link when there is one (Tether's own pages are on localhost and would not open on a phone).
- **`/mute`** takes `1h`, `30m`, up to 24 h, or `off`; anyone in the team may mute; approval and proposal cards still post.
- **Privacy mode:** the bot must see group messages: Settings shows "make the bot an admin (it also needs that to pin) or turn privacy off in @BotFather" when `getMe` says it can't read all messages.
- **Worker transport:** the port's authenticated loopback HTTP server is replaced by Node IPC on the child process (no listening socket, no token); the readiness frame stays.
- **Decoder:** macOS `afconvert` reads Ogg/Opus (checked on macOS 26), so no ffmpeg is needed on a Mac; ffmpeg is the fallback elsewhere.
- **Images in runs:** only answers (pings) get the photo; a task started from a photo's caption runs on the text.
- **Tether room for a Telegram team** is read-only for messages, but its cards keep their buttons (the same decisions as the Inbox).
